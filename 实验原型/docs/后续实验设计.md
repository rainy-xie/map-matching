# 围绕三个研究内容的后续实验设计

更新日期：2026-11-06。本文是待实施设计，依据[研究方案](../../研究方案.md)组织后续工作；当前完成状态统一记录在[研究进度与接力说明](../../研究进度与接力说明.md)。本文不增加实验完成状态，也不把候选方法写成已经成立的创新。v0.1 的输入、配置、源码与结果继续作为原有基线保留。

后续实验围绕“区域剖分建立—地图与运动特征参与剖分运算—基于知识化剖分覆盖的定位纠正”展开。先把前两项的对象、输入输出和人工可核验结果定义清楚；定位侧缺失的无地图运动对照可以同时推进。三项之间有依赖，但不必等全部定位对照结束后才研究剖分，也不必等真实 GPS 和参照齐备后才开展合成机制实验。

## 先建立共同的小样例

第一项具体交付是一份共同样例说明，包含小区域内的道路、开放区、混合地形边界、窄通道和未知属性区域。地图几何与属性来源需要分别记录；人工设定的地形、通行条件和运动参数都明确标为合成假设。样例先用于检查空间表示与知识运算，再根据定位问题添加带时间戳的观测和独立参照。

在运行算法前，人工写出可以核验的期望：区域边界和通道在哪里，哪些部分具有明确通行设定，哪些属性应保持未知，哪些跨区移动允许或禁止。混合地形单元怎样表达、运动特征是否改变移动评价，也要先说明预期含义。只表达“更平滑”或“看起来合理”不足以构成这些运算的核验标准。

不同研究内容共享地图与语义设定，但使用各自需要的输入。R1、R2 的几何或属性核验不必依赖 GPS；R3 的位置参照只供评测，不进入定位推断。若增加合成路线，采用人工关键点或独立的运动生成规则，并记录它与被测推断方法的关系，避免由待评价算法同时生成答案与预测。

## R1：区域剖分建立及其表示能力

先形成面状与体状用途、研究对象需要表达的空间关系及本文实际处理的说明。若选择面状处理，要交代保留的地形信息、简化内容与适用范围；若讨论高程属性或体状表示，要说明它解决什么问题、需要什么数据。是否实现体剖分由研究问题和依据决定，不预先要求同时实现完整二维与三维系统。

在此基础上确定少量有理由的剖分比较方案。当前均匀四边形格网可以作为基线，三角形、六边形、边界保持或自适应方式均是候选，尚未固定最终组合。动态生成也需要先定义触发条件、生成范围和更新内容，再判断是否成为本研究的方法要点。

R1 的比较首先看空间表示是否正确，包括区域覆盖、单元边界、邻接或连通表达，以及窄通道和关键地形边界是否得到保留。结合样例的人工期望，记录遗漏、额外覆盖、错误连通和通道丢失等具体情形。随后报告单元、候选与连接数量，生成、查询、更新的耗时及必要的存储成本；没有实现的操作不填写性能结果。

不同形状的同一标称边长并不自动意味着相同预算。比较时分别说明尺度和计算资源如何控制；可以在可比单元或候选数量、可比计算成本下观察表示质量，并在相近表示质量下比较成本。进入定位比较时，再固定地图信息与推断条件，避免把更多候选或更细尺度的收益直接归因于剖分方式。

本项应产出选型与简化依据、剖分结果及其核验记录。v0.1 已发现的量化误差和窄通道丢失可作为起点，但尚不是候选新方案的有效性证据。

## R2：地图知识与运动特征怎样参与剖分运算

先定义地图信息、运动特征和运算结果之间的关系。地图侧区分地形类别、明确通行限制、属性来源和未知信息；运动侧区分观察到的量、由 GPS 估计的量以及待校准参数。由同一 GPS 派生的速度或方向不能直接当作独立、无误差的新观测。

需要明确哪些信息附着在单元上，哪些描述单元之间的联系，哪些随运动状态变化。混合地形如何表达、重叠要素怎样处理、未知属性怎样传播，都需要有可核验的规则。面积占比、多类别表达、通行关系、时间或移动代价等可以作为候选表达；最终采用什么，取决于后续定位需要和能够取得的证据。

共同样例应至少覆盖地形边界穿过单元、同一单元包含多类地形、窄通道两侧的连接，以及未知属性不能自动变成可通行证据等情况。运动运算可以使用明确标为假设的参数，人工核验给定距离、时间和地形条件下的输出。若规则区分移动方向或地形变化，应另有能区分这些情况的样例；不预先要求实现尚无依据的运动模型。

评价分成两层：先检查输出是否遵循已经声明的知识与运动规则，再研究改变表达或参数时，下游可达性、移动评价和定位结果怎样变化。对规则的程序核验不能替代运动模型的现实有效性验证。合成样例可以验证运算机制，真实地形和运动员特征的赋值仍需来源、观测或校准依据。

本项应产出输入输出定义、知识与运动运算规则、人工期望结果及核验记录。部分信息可以预先计算，部分运算也可以在定位过程中按当前状态执行，不要求 R2 全部离线。当前丰台图层可以用于几何与来源处理；其缺失的跑通性、坡度和运动参数仍保留为缺口，不能为了完成本项而补造。

## R3：定位纠正效果与贡献分离

R3 接收有误差的位置观测，以及 R1、R2 提供的空间表示和计算依据。先明确输出是离散候选坐标、区域，还是其他坐标估计，并说明在线或离线条件。当前 HMM 风格 Viterbi 是可复用的离线基线，最终是否采用该框架仍需论证。

现有原始 GPS、仅地图候选、地图与运动评分三个方法继续保留。优先补充无地图但具有可比运动约束的对照，同时报告候选覆盖、数量、连接与计算成本；几何结构、候选离散和地图语义各自改变了什么，需要明确说明。仅把地图文件去掉、同时换一套候选或模型，不能视作只改变了一个因素。

后续消融分别回答三类问题：改变剖分表示而保持地图信息与推断条件尽量一致时，定位怎样变化；在同一空间表示上改变地图知识或运动运算时，结果怎样变化；保留同等信息和预算时，不同定位推断方法表现怎样。无法完全控制的差异应记录并限制结论，不预先把所有变化组合成一个“改进版”后只报告总收益。

评测继续保留所有时刻、回退和重启，报告坐标误差、失败情形、未知状态与计算成本。若输出只有区域，区域准确率与连续坐标误差分开解释。后续增加独立路线、参数选择与测试分离，以及适合研究问题的噪声和地图错误情形；所有合成设定均与真实观测区分。结果允许无改善或退化，不能按效果筛掉不利样例。

真实实验单独落实带时间戳的 GPS、地图来源与坐标/通行证据，以及质量明确的独立位置参照。只有检查点或区域标注时，结论限于对应评价范围。取得真实数据后再开展相应验证，不把合成效果升级为真实运动员定位精度结论。

## 推进与记录方式

方法上的依赖是：共同样例、R1 表示及 R2 运算定义先具备可检查的含义，随后才能开展对应的受控定位比较。既有基线的无地图运动对照、数据条件核实与前两项机制研究可以并行。这里仅规定实验依赖；当前任务优先级、已完成事项与近期交付统一由[研究进度与接力说明](../../研究进度与接力说明.md)维护。

后续实现、参数或场景改变时，在新版本与新运行目录保存输入、配置、源码哈希和结果，不覆盖 `runs/2026-11-02-v0.1-verified/`、旧验收或发布清单。活动文档可以持续更新，实际完成状态与证据入口同步写入根目录接力说明。本文中的设计只有在实现并核验后，才能转为完成事项。
