# v0.1.0 本轮运行、结果与失败记录

本轮从现有接力材料与数据核查结果出发，在新建的 `实验原型/` 内完成代码和实验。首条绕障碍轨迹于 2026-11-01 跑通；三个子代理随后曾因额度中断，用户要求继续后于 2026-11-02 完成各模块核查和整套实验。主代理维护共享接口、配置、依赖、CLI、集成检查和本记录，子代理分别负责地图、定位、评测限定文件，没有改写原始资料。

第一条轨迹运行后发现自由离路场景把装饰道路线标为已知通行面，与地图契约冲突。正式实验前将这条线的通行性改成 unknown，并增加全部场景建图测试；没有更改参照路线、噪声、种子或模型参数。图中失败/重启的相关连线同时断开，保留所有失败点和误差。这些是接口与展示正确性修复，不是根据结果优化参数。最终只读审查另发现部分运行报告误写“全部预设路线”，因此修正了运行范围说明并新增2项报告测试；为保持最终源码与结果完全对应，又生成了verified及verified-repeat两套验收结果。估计坐标与初次完整运行相同。

## 实际执行与版本

正式运行命令为 `./run.sh runs/2026-11-02-v0.1-verified`，重复命令为 `./run.sh runs/2026-11-02-v0.1-verified-repeat`。每套共 21 条轨迹，包含 7 种场景和 3 个噪声种子；每条 71 点，三种方法共 63 行统计，每种方法评价 1,491 个观测时刻。定位在独立子进程中运行。

环境为 Python 3.12.14、macOS 26.6.2 arm64、NumPy 2.3.5、Shapely 2.1.2、PyProj 3.7.2、Pyogrio 0.11.1、Matplotlib 3.10.7。具体解释器、源文件 SHA-256 和直接依赖版本保存在各结果目录的 `environment.json`，参数在 `config.json`，输入哈希保存在各轨迹目录。源码版本为 0.1.0，此目录未建立 Git 仓库，以哈希清单固定版本。

最终验收首套从建图、推断到评价/绘图的运行阶段共 70.45 s；重复套为 71.97 s。这里不包含前面的合成数据生成和真实地图重新裁切。每条 71 点轨迹的 HMM 纯推断为 1.85—3.36 s，平均 2.69 s，地图构建另计；这些是单机单次墙钟耗时，不是严格性能基准，更不是逐点在线延迟。

## 两类具体失败

低噪声开阔地的原始 GPS 每轴标准差只有 0.35 m，但输出被限制到 4 m 格网中心。此时地图没有提供可辨别的障碍信息，量化损失超过观测误差，地图与 HMM 两种结果相同。[种子20261101叠图](../runs/2026-11-02-v0.1-verified/results/open_low_noise_seed20261101/trajectory.png)保留了这种退化，而不是通过减小网格或改种子将它消除。

错误地图在实际合成空地上放入虚假矩形障碍。三次 HMM 运行共出现 5 个 no_candidates 回退点、6 个 reset_unreachable 重启点，全部纳入 213 点统计；即使没有失败标记的点，也可能被错误障碍推偏。[种子20261101叠图](../runs/2026-11-02-v0.1-verified/results/wrong_map_seed20261101/trajectory.png)与对应逐点 CSV 可定位误差增大的时段。回退不等于恢复成功，断开后的新片段也不证明存在可行的跨段运动。

另外，地图测试明确构造了一个连续空间存在 1 m 缝隙、4 m 网格无法表示的例子。它是剖分分辨率的失败边界，不计入当前七场景误差表。未来比较边界保持剖分时，应直接测这种拓扑损失，而不是只看平滑程度。

## 验收证据

33 项测试通过，包括 8 项地图、13 项定位、7 项评测、3 项独立进程集成测试和 2 项报告范围测试。定位的四时刻三候选样例逐一枚举 81 条路径，与 Viterbi 结果一致。非等间隔、速度门限、未知通行、失败回溯和输出对齐均有针对性检查。

[复现核查 JSON](../verification/final-reproducibility.json)确认两套运行的 84 个输入文件和 42 个预测坐标/状态文件逐字相同；63 行指标使用独立标准库代码从输出坐标重新计算一致。原始压缩包、开题资料、原始解包、文献和源 GPKG 共 233 个文件 SHA-256 与实现前相同。地图子代理还在临时目录重建裁图，四个派生文件逐字一致。

参照始终独立保存于 `reference/`。定位模块没有文件 I/O，命令进程不接收参照路径，审计钩子拒绝打开 reference 路径。集成测试把邻近参照改成无效文本再删除，预测仍逐字相同；观测混入参照列则被拒绝。该检查能发现本原型误读答案的错误，不构成强制系统沙箱。

## 下一步入口

目前已完成的是合成机制原型，不是论文最终算法。它采用非归一化转移势的离线 HMM 风格基线；若论文要求规范化概率模型、在线延迟或置信度，需要单独定义和验证。现有最大参照速度约 1.14—1.84 m/s，仍以步行尺度和独立高斯噪声为主，不能冒充越野跑或多路径误差验证。

下一轮先冻结本版，加入相同观测与候选预算下的无地图运动对照，检查地图约束、量化与时序先验各自的贡献；再用独立路线开展格网尺度与候选半径敏感性，最后比较保留边界的剖分。真实数据侧继续确认地图来源/坐标/通行性，并获取真实带时间戳 GPS 与独立位置参照。导师对二维/体剖分、离线/在线、AR范围的要求仍待确认，本原型不替代这些决定。
