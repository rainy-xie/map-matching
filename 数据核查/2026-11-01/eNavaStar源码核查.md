# eNavaStar 源码核查

核查日期：2026年11月1日。仅静态阅读，没有构建或执行程序，没有向外部上传文件。下列文件名和行号均相对于 `原始解包/eNavaStar/eNavaStar/`；源文件按 GB18030 解码后阅读。

## 结论

这份压缩包主要提供一个旧式二维地图绘图和数据组织框架，对理解“地图块—图层—点线面要素”的结构有参考价值。可见源码没有形成可以直接用于论文实验的定位纠正系统：没有发现 GPS 观测读取、HMM/Viterbi、轨迹匹配、区域剖分或距离计算算法；若只为完成当前论文，不宜先投入时间恢复这个旧应用。

这一判断针对已读取的源代码。`lib/eGDIBase.lib` 是未执行的二进制库，不能据此断言其中所有内部功能；配套头文件将其描述为绘图基础库。

## 已经提供了什么

工程文件 `eNavaStar.vcp:1–7` 标明 Microsoft eMbedded Visual Tools 和 Win32 (WCE ARM) Application，`eNavaStar.vcp:29` 指定 `clarm.exe`，第35–42行使用 MFC。因此它面向 Windows CE ARM 环境，不是当前 macOS 可以直接构建运行的普通 C++ 项目。工程第61行链接 `eGDIBase.lib`。

`GraLevel/GraLevel.h:28–36` 定义公路、铁路、河流、居民地、绿地和服务网点六种图层。第257–281行把数据块组织为行列编号，并让一个块包含多个图层；第16–25行的接图表记录跨块、跨图层要素的对应编号。这是存储和组织设计，尚不能等同于针对运动特征设计的区域剖分算法。

`GraLevel/GraEle/GraEle.h:5–13` 定义区域、多段线、点、文本和复合要素。第23–28行用点数及 X、Y 数组保存多边形/线串，第123–129行用两个 double 保存点。这里能确认二维几何结构，未见高度 Z、经纬度参考系、地图投影参数或实际测量单位。

`include/LGDIBase.h:91–103` 的坐标变换是用户坐标与绘图画布坐标之间的转换；第116–123行控制绘图原点和比例。不能把这些接口当作 WGS84、地方坐标系或地图投影之间的转换。`WorkSpace/NavaWks.cpp:35–47` 当前仅用 `(10,10)` 和 `(101,101)` 画演示矩形，第52–67行设置画布；第70–95行处理放大、缩小和漫游。

## 哪些部分尚未完成

`GraLevel/GraEle/GraEle.cpp:59–109` 中各类几何对象的 `ReadEle` 与 `OnDraw` 都是空函数。`GraLevel/LevelDist.cpp:23–53` 虽然写了居民地图层的要素读取循环，但调用的几何读取仍为空；公路、铁路、河流、绿地、服务点等读取函数也为空，例如第73–75、94–96、115–117、137–139、159–161行。文件名 `LevelDist.cpp` 不代表已经实现了距离计算。

此外，可见源码有明显未完成或有缺陷的路径。例如 `GraLevel/GraLevel.cpp:73–93` 把首次属性内存分配放在 `pat_TotalAtt != NULL` 条件中，而静态初值在第41行为 NULL；`GraLevel/GraLevel.cpp:115–125` 的 `AddLevel` 在判断空链表前就解引用链表。这里记录这些现象只是说明它不能被当成已验证的实验基线，没有修改源代码，也没有作全面代码审计。

## 地图文件与配套数据的线索

`GraLevel/GraLevel.cpp:112` 声明块文件扩展名 `BLO`，第170–182行按字节图层标志读取二进制块，第67–90行读取自定义的属性记录长度。`BaseData.h:2–22` 声明点、线、面、交通节点、组合交通要素和道路的数量/偏移量字段。

外层 ZIP 内未见 `.BLO` 地图块、GPS 记录、轨迹文件或坐标说明。可见源码没有读取 MapInfo `.TAB/.MAP/.DAT/.ID` 的完整实现，也没有随包提供从这些文件生成 `.BLO` 的转换工具。因此不能据此假设另一个“丰台数据.rar”可以被当前源码直接载入；那个压缩包应通过独立 GIS 读取来核查。

## 内嵌 RAR 的检查范围

内嵌 `eNavaStar.rar` 可以列出目录，包含同名工程、图层与图形源码，以及绘图库和资源，没有列出额外地图或轨迹文件。归档目录的时间戳主要为2001年，仅作文件元数据记录，不据此判断数据实际采集年代。

尝试使用系统 `bsdtar` 解到独立目录 `原始解包/eNavaStar_内嵌rar/` 时，工具报告 `BaseData.h: Prefix found: Inappropriate file type or format`，未完成正文解包。这个目录中的 `BaseData.h` 是失败产生的不完整文件，不可用作证据。内嵌目录显示部分文件大小与外层不同，例如 `GraEle.h` 为2733字节，而外层为2872字节，因此不能宣称两者内容完全一致。以上具体源码结论来自可正常阅读的外层 ZIP。

## 对论文的实际价值

可借鉴的主要是分层组织地图、表达点线面要素、组织块间关系的概念。论文算法仍需要独立建立可计算的地图语义、可达关系、GPS 观测和位置参照。建议把此包保留为历史工程参考，优先检查丰台地图的几何、属性、坐标及精细程度，再决定是否适合做区域划分原型；这个源码包本身不能补齐真实轨迹与独立定位参照。
