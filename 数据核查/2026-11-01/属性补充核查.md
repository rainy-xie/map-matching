# 丰台地图属性补充核查

核查日期：2026年11月1日。只读检查植被、水系、道路三个图层，没有修改源数据，没有读取或输出服务点的地址、电话等个人信息。统计明细保存于同目录的 `属性统计_标准库.json`。

## 结论

这些数据有真实可读取的类别编码和道路属性，但“字段存在”不能解释为“有有效观测值”。最有用的现成信息是道路类别、宽度、长度、车道数、始终节点号，以及水系类别。植被编码只有一种，缺少据此区分植被通行难度的依据。坡度和平均车速等字段全部使用疑似缺失值，不适合直接进入运动模型。

## 属性读取方法和边界

使用 Python 标准库读取 `.DAT` 中的 DBF式表头：偏移4的4字节无符号小端整数为记录数，偏移8、10的2字节无符号小端整数分别为表头长度和记录长度；字段描述从偏移32开始，每项32字节。三张表的字段描述类型均为 `C`，因此不能把所有字段简单按普通DBF文本读数。

本次以配套 `.TAB` 的字段顺序和类型为准：`Integer` 为4字节小端有符号整数，`Smallint` 为2字节小端有符号整数，`Float` 为8字节小端双精度，`Char` 按声明长度、GB18030解码，并去掉结尾NUL和空格。逐项验证了描述字段宽度、TAB预期宽度、记录总长度、文件总长度和表尾标识的一致性。每条记录首字节 `0x20` 表示本次统计的有效记录，`0x2A` 删除记录排除。

验证结果：植被表730条，表头161字节、记录61字节；水系表104条，表头193字节、记录81字节；道路表26147条物理记录，表头1825字节、记录1892字节，其中2条标记删除，以下道路统计以26145条有效记录为分母。没有遇到非有限浮点数。

这种独立解析足以确认字节内容和分布，但尚未与GIS驱动交叉核验，不读取 `.MAP` 几何，也不验证单位、坐标系、类别字典、测量精度及字段更新时间。没有将文件时间戳当成采集时间。`-999999.9`、`-32767` 被标为“疑似缺失哨兵”，在获得数据字典前不将其解释成正式标准定义。

## 植被与水系

植被共730条，编码全部为 `220200`，显示等级全部为7。说明存在分类编码，但当前编码本身没有进一步区分林地密度、灌木、草地或可跑通性。名称字段虽然730条均非空字节串，其中661条是字面字符串 `NULL`，只有69条非NULL名称记录。不能从字段名或非空计数推断具有完整植被语义。

水系共104条，编码有四种：`160401` 为73条，`160201` 为25条，`161103` 为4条，`160405` 为2条。编码具体代表河流、湖泊或其他要素，需要原始字典才能确认；不能直接以这些数字指定可穿越性。名称中90条为 `NULL`，14条为非NULL名称；“河流代码”104条全部是字面字符串 `NULL`，没有可用区分信息。

## 道路字段的可用性

| 字段 | 26145条有效道路记录的实际内容 | 对论文的含义 |
| --- | --- | --- |
| 编码 | 11种非零编码 | 可以形成类别分组，语义需字典 |

| 道路技术等级 | 1—6均有记录 | 类别存在，含义需核对 |
| 车道数 | 1—7，主要为1或2 | 有道路属性；不是运动员速度信息 |
| 始结点号、终结点号 | 全部非零，分别18794、19646种值 | 可探索路网连接，仍需检查几何端点与编号对应 |

| 路段高度限制、宽度限制、载重限制 | 全部为 `-999999.9` | 疑似缺失 |

| 道路名称 | 16399条为字面 `NULL`，9746条非NULL | 非空文本不等于已知道路名称 |

这批属性能支持“从现有地图构造空间表示”的初步工作，也能帮助筛选区域划分的语义输入。但是它不能提供运动员观测、GPS时间序列或定位真值。尤其不能把道路最大纵坡的缺失占位当成地形坡度，把城市道路等级或最高限速直接转换成越野跑速度。
